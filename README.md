# Austin Dangerous Intersections — Final Version

A machine learning project that predicts high-risk intersections in Austin, TX using 229,841 crash records from the City of Austin Open Data Portal (2014–2026). Supports both **coordinate-based** and **street name-based** lookup, with a full Flask web app for single and batch predictions.

## Project Overview

This project takes raw Austin crash report data and builds an end-to-end pipeline:

1. **Clean** the data (remove deleted records, fix bad timestamps, normalize nulls via InsightFlow)
2. **Parse** intersection addresses from the `Address` column (`"N LAMAR BLVD & W 6TH ST"`)
3. **Engineer features** per ~100m grid cell (speed limit, pedestrian rate, night crash rate, etc.)
4. **Train an XGBoost classifier** to predict whether a location is in the top 5% most dangerous
5. **Serve predictions** via a Flask web app with an embedded Leaflet map

---

## Features

- **Dual input modes** — enter lat/lon coordinates or street names (order doesn't matter: `A & B` matches `B & A`)
- **Single lookup** — get instant risk prediction with confidence score and plain-English explanation
- **Batch upload** — upload a CSV of locations, download results as CSV
- **Interactive map** — embedded Leaflet map showing top 60 crash hotspots in Austin
- **14-feature model** — speed limit, pedestrian/bike/motorcycle rates, rush hour, night crashes, construction zones
- **No data leakage** — `total_danger_score` used only for labeling, never as a model feature
- **SMOTE on training only** — synthetic oversampling applied after train/test split
- **InsightFlow integration** — structured data quality audit before cleaning

Run this inside a Jupyter notebook cell:

```python
import sys
print(sys.executable)
# Example output: C:\Users\nasim\env\Scripts\python.exe
```

### Step 2 — Install dependencies into that Python

Open **PowerShell** and use the exact path printed above:

```powershell
C:\Users\nasim\env\Scripts\pip.exe install -r E:\Jupyter\Dangerous_Intersections_Austin\FinalVersion\requirements.txt
```

> **Why not just `pip install`?**
> If your Jupyter kernel runs inside a virtual environment, running `pip` from a plain terminal
> installs into the global Python — a different location the kernel cannot see.
> Always use the `pip.exe` that lives alongside the kernel's `python.exe`.

### Step 3 — Verify

Run this in a Jupyter cell to confirm all packages loaded:

```python
import pandas, numpy, sklearn, imblearn, xgboost, joblib, flask, folium
import xgboost as xgb
print('sklearn :', sklearn.__version__)
print('xgboost :', xgb.__version__)
print('All good ✅')
```

## How to Run

### 1. Run the Notebook (required first)

Open and run all cells in [`notebook/crash_analysis_v2.ipynb`](notebook/crash_analysis_v2.ipynb).

**What it does (in order):**

| Step | What happens |
|------|-------------|
| 1 | Loads 229,841 raw crash records |
| 1.5 | InsightFlow data quality audit (null-like strings, column types, duplicates) |
| 2 | Cleans data — removes deleted records, fixes timestamps, normalizes nulls |
| 3 | Parses `Address` column into `primary_street` / `secondary_street` |
| 4 | Engineers 14 features per crash (danger score, time flags, user type flags) |
| 5 | Aggregates crashes into ~100m grid cells, labels top 5% as high-risk |
| 6 | Builds bidirectional intersection lookup table |
| 7 | Exploratory analysis — 6 charts saved to `images/` |
| 8 | Trains XGBoost with SMOTE (on training fold only) |
| 9 | Evaluates model — classification report, ROC-AUC, 5-fold CV |
| 10 | Feature importance chart |
| 11 | Generates 4 Folium maps saved to `maps/` |
| 12 | Saves model and metadata to `models/` |

**Expected runtime:** 3–8 minutes depending on your machine.

**Expected output after running:**
```
✅ XGBoost available
Ready.
...
Saved: data/grid_summary_v2.csv        (~18,000 rows)
Saved: data/intersection_lookup_v2.csv (~300,000+ rows)
Saved: models/danger_model_v2.pkl
Saved: models/model_meta.pkl
```

### 2. Start the Flask App

Open **PowerShell**, navigate to the `app/` folder, and run:

```powershell

C:\Users\nasim\env\Scripts\python.exe app.py
```

> Replace `C:\Users\nasim\env\Scripts\python.exe` with whatever path `sys.executable` printed in your kernel.

You should see:
```

```

Open your browser and go to **http://127.0.0.1:5000**

> The Flask app will fail to start if the notebook has not been run yet — it needs
> `models/danger_model_v2.pkl` and `data/grid_summary_v2.csv` to exist.

## Using the Web App

### Single Intersection Lookup (`/`)

Two input options — use whichever you have:

**Option A — Coordinates:**
```
Latitude : 30.2672
Longitude: -97.7431
```

**Option B — Street Names:**
```
Primary Street  : N Lamar Blvd
Secondary Street: W 6th St
```

Also set **Hour of Day** (0–23) and **Day of Week** (0 = Monday, 6 = Sunday) to factor in time patterns.

The result shows:
- **High Risk / Not High Risk** badge
- Confidence percentage with a visual bar
- Stats: total crashes, deaths/crash, injuries/crash, speed limit, pedestrian rate, night crash rate
- Plain-English explanation of why the model made that prediction
- Map pinned to your queried location

### Batch Upload (`/upload`)

Upload a CSV file with multiple locations. Required columns (choose one pair):

```csv
latitude,longitude,hour,dayofweek
30.289,-97.723,8,1
30.348,-97.712,17,4
```

```csv
primary_street,secondary_street,hour,dayofweek
n lamar blvd,w 6th st,9,2
e riverside dr,s congress ave,18,4
```

`hour` and `dayofweek` are optional — defaults to hour=12, dayofweek=2 if omitted.

Click **Download CSV** to export all predictions.

## Dataset

| Field | Value |
|-------|-------|
| Source | [City of Austin Open Data Portal](https://data.austintexas.gov) |
| File | `Austin_Crash_Report_Data_-_Crash_Level_Records_20260524.csv` |
| Records | 229,841 |
| Date range | 2014–2026 |
| Key column | `Address` — intersection format: `"STREET_A & STREET_B"` |

**Danger score formula** (per crash):
```
danger_score = death_cnt × 10
             + sus_serious_injry_cnt × 5
             + nonincap_injry_cnt × 2
             + poss_injry_cnt × 1
```

## Model Details

| Item | Value |
|------|-------|
| Algorithm | XGBoost (`GradientBoostingClassifier` fallback if XGBoost not installed) |
| Label | Top 5% grid cells by cumulative danger score = High Risk |
| Features | 14 (see below) |
| Class imbalance | Handled with SMOTE — applied on training fold only |
| Train/test split | 80/20 stratified |
| Evaluation | Classification report + ROC-AUC + 5-fold cross-validation |

**14 Features:**

| Feature | Description |
|---------|-------------|
| `total_crashes` | Number of crashes in grid cell |
| `death_rate` | Average deaths per crash |
| `serious_injury_rate` | Average suspected serious injuries per crash |
| `injury_rate` | Average total injuries per crash |
| `avg_speed_limit` | Mean posted speed limit at crash sites |
| `pedestrian_rate` | Fraction of crashes involving pedestrians |
| `bicycle_rate` | Fraction involving cyclists |
| `motorcycle_rate` | Fraction involving motorcyclists |
| `night_crash_rate` | Fraction occurring 8pm–5am |
| `rush_hour_rate` | Fraction occurring 7–9am or 4–7pm |
| `weekend_rate` | Fraction on Saturday/Sunday |
| `construction_zone_rate` | Fraction in active construction zones |
| `avg_hour` | Mean hour of crashes |
| `avg_day_of_week` | Mean day of week of crashes |

**Why no leakage?**
The old version included `total_danger_score` as a model feature — the same value used to define the high-risk label. That gave 100% accuracy because the model just learned to read the answer. Here, `total_danger_score` is used only to set the label threshold and is never passed to the model.
